## Code Comments & Documentation

- Do NOT add explanatory comments that describe what the code is doing (e.g. `// loop over items`, `// return the result`)
- Comments must explain WHY the code exists or why a particular approach was chosen — never narrate the code itself
- Do NOT add file/section header comments to test files (e.g. `// --- Tests for Foo ---`, `// Unit tests`, `// Setup`)
- JSDoc / docstrings for functions and classes must describe what the function or class does (its contract, purpose, side-effects), NOT how it is implemented internally — omit any mention of internal variables, loops, or algorithmic steps
